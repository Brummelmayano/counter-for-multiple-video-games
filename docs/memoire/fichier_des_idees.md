Sujet : Comptage adaptatif des parties de jeux vidéo

L’objectif est de faire évoluer notre précédent compteur (voir l'article "Intelligent match counter in a video game arena" publié sur IEEE Access. ) vers un système multi-jeux capable de détecter automatiquement, en temps réel, quand une partie de jeu, par exemple un match, un combat ou une course se termine, puis de s’adapter à de nouveaux jeux sans devoir reprogrammer toute la logique de comptage à chaque fois.

Pour cela, on va s'interesser au gameplay. Selon le Cambridge Dictionary, ce terme peut désigner l’activité consistant à jouer à un jeu vidéo. et dans notre contexte, on va donc s'interesser aux événements observables qui apparaissent au cours de cette activité.

l'idée c'est de stocker ces événements dans une structure de donnés par exemple ou un fichier csv, les stocker l'un à la suite de l'autre selon leurs ordre d'arrivé dans le temps. puis cette structure de données sera ensuite ensuite analysés dans leur ordre temporel par un modèle temporel léger afin de déterminer quand une partie à compter est réellement terminé. selon le jeu en cours,   pour detecter le jeu en cours, et le type de jeu, on peux carrement poser la question de savoir, de quel jeux video s'agit il?   et cela peux etre classé dans  quel type de jeux videos pamis les types suivantes : sport de kombat, football...  quelle question faut t-il poser pour extraire les événements observables qui apparaissent au cours de cette activité (gameplay)?  car ces questions nous permetrons d'extraire les evenements qui nous permettrons de savoir si la pratie est terminé

alors quel sont ces evenement? voici la reponse pour les uns. ces evenement peuvent etre basé sur les timing, les noms des equipes, des kombatant ou le score affichées pour savoir si c'est la meme partie(match,combat) ou la partie suivante afin de compter la nouvelle partie:, tu peux voir notre article(intelligent match counter in a video game arena) pour voir notre ancienne idéé
